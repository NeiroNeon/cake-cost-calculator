# Архитектура

## Решение по миграции

Исходный калькулятор — зрелое автономное приложение на одном HTML-файле с большим количеством проверенного интерфейсного поведения, мобильных оверлеев и обратной совместимостью. В этом релизе сохранено его ядро, а расчётные функции выделены в чистый ES-модуль. Это сознательный выбор в пользу функциональной совместимости: переписывание интерфейса на новый фреймворк без полного набора эталонных сценариев могло бы сломать существующие пользовательские данные и UX.

## Слои

- `app/index.html` — приложение и его интерфейс.
- `app/src/domain.js` — расчётные функции и валидация импортируемых данных без доступа к DOM.
- `site/` — публичная motion-страница и интерактивный демонстрационный калькулятор.
- `sw.js` / `manifest.webmanifest` — установка и кэширование приложения.
- `tests/` — unit-тесты доменной логики на Node.js.

## Хранение

`localStorage[bento_cost_v3]` хранит объект `{ products, calculators }`. При старте приложение читает `bento_cost_v3`, а если его нет — `bento_cost_v2`. Миграция сохраняет существующую схему; ID продуктов не меняются.

## Публикация

Сайт и приложение — статические ресурсы. Backend не нужен. GitHub Actions проверяет доменные тесты и публикует корень репозитория в GitHub Pages. Для project pages ссылки заданы относительными путями.

## Границы

Нет серверной синхронизации, пользовательских аккаунтов, облачного хранения или аналитики. Service worker кэширует интерфейс; это не механизм резервного копирования пользовательских данных.
